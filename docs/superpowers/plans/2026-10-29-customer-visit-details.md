# Customer Visit Details Implementation Plan

**Goal:** Show only pending arrivals as compact customer dashboard cards and open the correct saved visit from every upcoming/tracker card.

**Architecture:** Preserve the history/cache/polling contract for grooming. Narrow the dashboard-only clinic list to pending unchecked registrations; read clinic details on demand through an authenticated owner-scoped endpoint. Reuse the grooming native dialog shell, confirmation fields, print presentation, and cancellation request/confirmation flow.

**Constraints:** Customer dashboard scope; existing portal tokens and Phosphor icons; no migrations, new dependencies, polling, manual localhost functional testing, commits, or deployment.

1. Update existing dashboard regression expectations for eligibility, hidden empty sections, Manila dates, whole-card actions, independent session IDs, and expansion. Add clinic endpoint ownership/payload coverage to the existing clinic feature tests. Run changed tests before implementation to establish failures.
2. Filter clinic history at query and presentation levels; add `GET /clinic/registrations/{id}` with explicit safe fields and eager pet loading. Verify owner access, other-owner/missing/unauthenticated rejection, check-in removal, and no staff/clinical data exposure.
3. Render shared compact upcoming buttons and stretched tracker buttons. Keep Show all/fewer above the overlay; use the whole tracker section only for one session. Preserve conditional DOM updates and restore focus by stable IDs after meaningful refreshes.
4. Extend the existing lazy summary module with clinic presentation and shared dialog lifecycle. Preserve printing; expose eligible cancellation inside the summary and reuse the confirmation/request flow. Guard lazy imports, repeated reads, close/reopen races, and refreshes of an open visit.
5. Run dashboard/summary/clinic/cancellation/cache regressions, production build, and diff checks. Inspect only the existing customer browser tab for visual consistency; leave navigation, input, OTP, and password workflows to the user.

**Review focus:** Missing/invalid dates must never fabricate timestamps; Manila midnight uses submission date, not today. Multiple sessions must never share a target. Polls must preserve focused controls and active modal state. Cancellation must retain payment/state/count safeguards. Removed clinic cards must update an open detail without becoming a clinic tracker.
